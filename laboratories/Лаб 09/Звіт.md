## Теоретичні відомості
Образ містить файлову систему й налаштування запуску, а контейнер є його ізольованим виконуваним екземпляром. Docker CLI керує збіркою, створенням, запуском, перевіркою та видаленням контейнерів.
Мережа Docker забезпечує DNS-імена між контейнерами. Іменований том зберігає дані незалежно від контейнера; монтування :ro дозволяє лише читання. Змінна APP_PORT передає конфігурацію процесу. trap EXIT забезпечує прибирання ресурсів навіть у разі помилки.

## Хід виконання
Власний проєкт — Python HTTP-сервіс app.py у GitHub-репозиторії Sh1kami/CI_CD. Для ізольованого тестування сценарій збирає ціль tester, де виконуються сім модульних тестів, а потім production-образ.
container_check.sh створює мережу, том і контейнер з унікальними іменами. У том окремим одноразовим контейнером записується owner.txt. Основний контейнер отримує цей том лише для читання й APP_PORT=3000.
Сценарій очікує healthy з обмеженою кількістю спроб. Інший контейнер у тій самій мережі звертається до http://app:3000/health. Далі docker exec перевіряє вміст тому, а docker inspect — стан контейнера. EXIT-trap видаляє лише ресурси поточного запуску та зберігає код завершення.

### scripts/container_check.sh

```
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")/.."
suffix="$$"
network="panchyshkin-net-$suffix"
volume="panchyshkin-results-$suffix"
container="panchyshkin-app-$suffix"
cleanup() {
  rc=$?
  trap - EXIT
  docker rm -f "$container" >/dev/null 2>&1 || true
  docker network rm "$network" >/dev/null 2>&1 || true
  docker volume rm "$volume" >/dev/null 2>&1 || true
  exit "$rc"
}
trap cleanup EXIT
docker build --target tester -t panchyshkin-cicd:tests .
docker build --target production -t panchyshkin-cicd:lab10 .
docker network create "$network"
docker volume create "$volume"
docker run --rm -v "$volume:/results" python:3.12-slim \
  python -c "from pathlib import Path; Path('/results/owner.txt').write_text('Panchyshkin Bohdan 3PRs/3')"
docker run -d --name "$container" --network "$network" --network-alias app \
  -e APP_PORT=3000 -v "$volume:/results:ro" panchyshkin-cicd:lab10
ready=0
for ((attempt=1; attempt<=40; attempt++)); do
  state=$(docker inspect --format '{{.State.Health.Status}}' "$container")
  if [[ "$state" == healthy ]]; then ready=1; break; fi
  sleep 2
done
((ready == 1)) || { docker logs "$container"; exit 1; }
docker run --rm --network "$network" python:3.12-slim python -c \
  "import urllib.request; print(urllib.request.urlopen('http://app:3000/health').read().decode())"
docker exec "$container" cat /results/owner.txt
docker inspect --format 'state={{.State.Status}} health={{.State.Health.Status}}' "$container"

```

## Результати виконання
Сім модульних тестів успішні. Контейнерний HTTP-клієнт отримав status=ok та ім’я автора. Вміст owner.txt прочитано з тому; стан основного контейнера — running, healthy. Після перевірки тимчасові мережа, том і контейнер видалені, код сценарію 0.
