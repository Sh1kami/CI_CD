## Теоретичні відомості
Jenkins виконує автоматизовані задачі на агенті. Declarative Pipeline описує етапи у Jenkinsfile мовою Groovy DSL. Блок agent визначає виконавця, stages задає послідовність, а steps — операції кожного етапу.
Плагін Git забезпечує checkout, а Pipeline — виконання конвеєра. Команда git log -2 обмежує вивід двома комітами. Вона читає історію Git, тому після clone має виконуватися в тому самому робочому каталозі.

## Хід виконання
Побудовано образ на основі jenkins/jenkins:lts-jdk21. Через jenkins-plugin-cli встановлено workflow-aggregator, git і timestamper. Jenkins запущено на localhost:8099 із постійним томом даних.
Для відтворюваного навчального запуску init.groovy створює задачу lab08-last-two-commits з Jenkinsfile та запускає її. Сервіс прив’язаний лише до loopback. Для постійного сервера необхідно налаштувати користувачів і права доступу.
Етап Clone отримує гілку master відкритого xvadim/number_facts. Етап Last two commits друкує хеш, автора, дату та повідомлення двох комітів. Увесь pipeline обмежений п’ятьма хвилинами.

### lab08/Dockerfile

```
FROM jenkins/jenkins:lts-jdk21
RUN jenkins-plugin-cli --plugins workflow-aggregator git timestamper
COPY lab08/init.groovy /usr/share/jenkins/ref/init.groovy.d/lab.groovy
COPY lab08/Jenkinsfile /usr/share/jenkins/ref/lab.Jenkinsfile
ENV JAVA_OPTS="-Djenkins.install.runSetupWizard=false"

```

### lab08/Jenkinsfile

```
pipeline {
    agent any
    options { timestamps(); timeout(time: 5, unit: 'MINUTES') }
    stages {
        stage('Clone') {
            steps { git url: 'https://github.com/xvadim/number_facts.git', branch: 'master' }
        }
        stage('Last two commits') {
            steps { sh 'git --no-pager log -2 --date=iso-strict --format="%h | %an | %ad | %s"' }
        }
    }
}

```
