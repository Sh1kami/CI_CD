## Тема роботи
Основи систем керування версіями. Git

## Мета роботи
Ознайомитися з можливостями Git для керування версіями програмного забезпечення.

## Завдання
Створити новий репозиторій, додати кілька файлів, створити гілку, змінити в ній один із файлів, злити зміни в основну гілку та відобразити команди у звіті.

## Теоретичні відомості
Git — розподілена система керування версіями. Робоче дерево містить поточні файли, індекс — підготовлені до коміту зміни, а каталог .git — історію та службові дані. git add переносить зміни до індексу, git commit створює знімок.
Гілка є рухомим посиланням на коміт. git switch -c створює її та перемикає робоче дерево. git merge об’єднує історії. Параметр --no-ff зберігає окремий merge-коміт, навіть якщо було можливе fast-forward-злиття.

## Хід виконання
У lab03/repository виконано git init -b main. Ім’я автора налаштовано локально для цього репозиторію, без зміни глобальних налаштувань. Додано README.md і hello.sh та створено початковий коміт.
Створено гілку develop. У README.md дописано версію 1.0 та ім’я автора, після чого зміну збережено окремим комітом. Після повернення до main виконано git merge --no-ff develop.
Команди git log --oneline --graph --all і git status --short підтвердили граф історії та чисте робоче дерево. Повну історію збережено у lab03-history.bundle, який можна клонувати командою git clone lab03-history.bundle restored-lab03.

```sh
git init -b main
git config user.name "Панчишкін Богдан Олександрович"
git config user.email "panchyshkin@users.noreply.github.com"
git add README.md hello.sh
git commit -m "Initial project files"
git switch -c develop
# Додати у README.md рядок Version 1.0
git add README.md
git commit -m "Document version 1.0"
git switch main
git merge --no-ff develop -m "Merge develop into main"
git log --oneline --graph --all
git status --short
```
