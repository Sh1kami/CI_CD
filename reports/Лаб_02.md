## Тема роботи

## Мета роботи
Ознайомитися з додатковими можливостями Bash для написання сценаріїв CI/CD.

## Завдання
Створити скрипт перевірки існування, доступності для читання й запису, ненульового розміру та виконуваності файлів, імена яких задаються масивом. Створити .env з URL і APP_PORT та Bash-скрипт перевірки сервісу через curl на цьому порту.

## Теоретичні відомості
Масив Bash зберігає кілька значень; розгортання "${files[@]}" зберігає кожне ім’я окремим елементом, зокрема за наявності пробілів. Оператори -e, -r, -w, -s та -x перевіряють відповідно існування, читання, запис, розмір і виконуваність.
Файл .env відокремлює конфігурацію від програми. set -a експортує змінні, оголошені під час source. Оскільки source виконує shell-код, завантажувати слід лише власний довірений файл. Секретний .env виключено з Git, а демонстраційний .env.example збережено.
curl --fail повертає ненульовий код для HTTP 400 і вище. Тайм-аути обмежують очікування з’єднання та відповіді, що запобігає зависанню CI-задачі.

## Хід виконання
У check_files.sh створено масив імен, який можна перевизначити аргументами командного рядка. Вкладений цикл виконує п’ять перевірок для кожного шляху та друкує таблицю yes/no. Перевірки відображають права саме поточного користувача.
У lab02/.env.example задано URL=http://127.0.0.1 та APP_PORT=3000. Скрипт check_url.sh перевіряє схему і хост URL, числовий порт 1–65535, після чого звертається до /health. Значення 10# примусово задає десяткове трактування порту.
Для перевірки запущено локальний app.py на порту 3000, скопійовано .env.example до .env і виконано обидва скрипти. Після HTTP-перевірки локальний процес зупинено.

### lab02/check_files.sh

```
#!/usr/bin/env bash
set -euo pipefail
files=("${@}")
if ((${#files[@]} == 0)); then
  files=("lab01/greeting.sh" "README.md" "missing.txt")
fi
printf 'file\texists\tread\twrite\tnonempty\texecutable\n'
for file in "${files[@]}"; do
  flags=()
  for property in e r w s x; do
    if test "-$property" "$file"; then flags+=(yes); else flags+=(no); fi
  done
  printf '%s\t%s\t%s\t%s\t%s\t%s\n' "$file" "${flags[@]}"
done

```

### lab02/.env.example

```
URL=http://127.0.0.1
APP_PORT=3000

```

### lab02/check_url.sh

```
#!/usr/bin/env bash
set -euo pipefail
env_file=${1:-lab02/.env}
# source executes shell code: use only your own trusted configuration.
[[ -f "$env_file" ]] || { echo "Missing configuration: $env_file" >&2; exit 1; }
set -a
source "$env_file"
set +a
: "${URL:?URL is required}" "${APP_PORT:?APP_PORT is required}"
[[ "$APP_PORT" =~ ^[0-9]{1,5}$ ]] || exit 2
port=$((10#$APP_PORT))
((port >= 1 && port <= 65535)) || exit 2
[[ "$URL" =~ ^https?://[^/:]+$ ]] || { echo 'URL must contain scheme and host only' >&2; exit 2; }
curl --fail --show-error --silent --connect-timeout 3 --max-time 10 "${URL}:${port}/health"
printf '\n'

```

## Результати виконання
Перевірка файлів охопила наявний sh-сценарій, README.md і відсутній missing.txt. curl отримав відповідь /health зі status=ok; обидва скрипти завершилися з кодом 0. У Windows модель виконуваності файлів у Git Bash може відрізнятися від POSIX-прав Linux.
