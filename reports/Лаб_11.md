## Тема роботи
Багатоконтейнерні середовища Docker Compose для розробки та інтеграційного тестування

## Мета роботи
Навчитися описувати Compose V2, готовність сервісів, мікросегментацію мереж і багатофайлові конфігурації для CI/CD.

## Завдання
Створити compose.yaml, compose.override.yaml, compose.ci.yaml і Bash-раннер. Передбачити власний застосунок, СУБД, кеш, одноразову міграцію зі service_completed_successfully та інтеграційний раннер із профілем ci.

## Теоретичні відомості
Compose описує сервіси, мережі й томи декларативно. Звичайний порядок запуску не гарантує готовності: service_healthy очікує успішний healthcheck, service_completed_successfully — завершення одноразового контейнера з кодом 0.
Базова конфігурація містить спільну архітектуру. compose.override.yaml додає локальний порт і bind mount для розробки. CI явно передає лише базовий та CI-файли, тому локальний override не відкриває зайві порти й не підміняє код образу.
Профіль ci активує тестовий сервіс. Мережа backend із internal=true ізолює PostgreSQL і Redis; мережа frontend з’єднує застосунок із тестами. Застосунок приєднаний до обох мереж, а тестовий контейнер не має прямого маршруту до бази.

## Хід виконання
Описано п’ять сервісів: db на PostgreSQL 16, cache на Redis 7, migrate із production-образу роботи 10, app із того самого образу та tests на Python 3.12. Порти СУБД й кешу на host не публікуються.
Спочатку db має стати healthy. migrate створює таблицю counter і початковий рядок ідемпотентно. Лише після успішної міграції та готовності cache запускається app. Його /health перевіряє справжні з’єднання з PostgreSQL та Redis.
CI-скрипт перевіряє конфігурацію, збирає образ із метаданими поточного Git-коміту й очікує готовності app. Одноразовий tests перевіряє HTTP, збільшення лічильника між двома запитами та запис/читання Redis. Його код визначає результат CI.
EXIT-trap зберігає журнали та ps -a, після чого виконує down --volumes лише для унікального тестового Compose-проєкту. База в CI має тимчасовий том; локальний запуск має окремий іменований том.

### compose.yaml

```
name: panchyshkin-cicd
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: cicd
      POSTGRES_USER: cicd
      POSTGRES_PASSWORD: ${DB_PASSWORD:?Set DB_PASSWORD in .env}
    volumes:
      - db_data:/var/lib/postgresql/data
    networks: [backend]
    healthcheck:
      test: [CMD-SHELL, 'pg_isready -U cicd -d cicd']
      interval: 3s
      timeout: 3s
      retries: 30
  cache:
    image: redis:7-alpine
    networks: [backend]
    healthcheck:
      test: [CMD, redis-cli, ping]
      interval: 3s
      timeout: 3s
      retries: 30
  migrate:
    image: panchyshkin-cicd:lab10
    build:
      context: .
      target: production
      args:
        VCS_REF: ${VCS_REF:-unknown}
        BUILD_DATE: ${BUILD_DATE:-unknown}
    environment:
      DATABASE_URL: postgresql://cicd:${DB_PASSWORD}@db:5432/cicd
    command: [python, migrate.py]
    healthcheck:
      disable: true
    networks: [backend]
    depends_on:
      db:
        condition: service_healthy
    restart: 'no'
  app:
    image: panchyshkin-cicd:lab10
    build:
      context: .
      target: production
      args:
        VCS_REF: ${VCS_REF:-unknown}
        BUILD_DATE: ${BUILD_DATE:-unknown}
    environment:
      APP_PORT: '3000'
      DATABASE_URL: postgresql://cicd:${DB_PASSWORD}@db:5432/cicd
      REDIS_URL: redis://cache:6379/0
    networks: [frontend, backend]
    depends_on:
      migrate:
        condition: service_completed_successfully
      cache:
        condition: service_healthy
  tests:
    image: python:3.12-slim
    profiles: [ci]
    working_dir: /tests
    volumes:
      - ./tests/integration.py:/tests/integration.py:ro
    command: [python, integration.py]
    environment:
      BASE_URL: http://app:3000
    networks: [frontend]
    depends_on:
      app:
        condition: service_healthy
networks:
  frontend: {}
  backend:
    internal: true
volumes:
  db_data: {}

```

### scripts/docker_compose_ci_runner.sh

```
#!/usr/bin/env bash
set -euo pipefail
cd "$(dirname "$0")/.."
mkdir -p evidence
: "${DB_PASSWORD:?Set DB_PASSWORD or export it from your environment}"
export VCS_REF BUILD_DATE
VCS_REF=$(git rev-parse HEAD)
BUILD_DATE=$(date -u +%Y-%m-%dT%H:%M:%SZ)
project="${COMPOSE_PROJECT_NAME:-panchyshkin-ci-$$}"
dc=(docker compose -p "$project" -f compose.yaml -f compose.ci.yaml --profile ci)
cleanup() {
  rc=$?
  trap - EXIT
  "${dc[@]}" logs --no-color > evidence/compose.log 2>&1 || true
  "${dc[@]}" ps -a > evidence/compose-ps.txt 2>&1 || true
  "${dc[@]}" down --volumes --remove-orphans || true
  exit "$rc"
}
trap cleanup EXIT
"${dc[@]}" config --quiet
"${dc[@]}" build
"${dc[@]}" up -d --wait app
"${dc[@]}" run --rm --no-deps tests

```

### tests/integration.py

```
import json
import os
import urllib.request
base = os.getenv('BASE_URL', 'http://app:3000')
def get(path):
    with urllib.request.urlopen(base + path, timeout=5) as response:
        assert response.status == 200
        return json.load(response)
assert get('/health')['status'] == 'ok'
first = get('/visits')
second = get('/visits')
assert second['visits'] == first['visits'] + 1
assert first['cached'] == first['visits']
assert second['cached'] == second['visits']
print('PASS health, database increment, Redis read/write')

```
